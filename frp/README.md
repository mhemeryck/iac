# Home Assistant remote access

Expose `https://hass.mhemeryck.xyz` through the existing remote Traefik ingress.
Forward requests to the home cluster through an authenticated WSS tunnel.

## Resources

- Terraform root: `envs/mhemeryck/frp/`
- State key: `frp/terraform.tfstate`
- Namespace: `frp`
- Server image: `ghcr.io/fatedier/frps:v0.71.0`
- Public tunnel: WSS on port `443`, path `/~!frp`
- Internal tunnel listener: `frp-tunnel:7000`
- Internal backend: `homeassistant-tunnel:80`, mapped to proxy port `8080`
- HTTPS certificate: `homeassistant-remote-tls`, issued by `letsencrypt`
- Token: generated by Terraform and stored in the S3-backed state

The ingress serves HTTPS only.
The HTTP challenge uses the separate solver ingress created by cert-manager.
Traefik terminates TLS and picks up certificate renewals automatically.
The tunnel route preserves `/~!frp` when forwarding to the server.
The `/` route forwards Home Assistant requests through proxy port `8080`.
Both server ports are exposed through internal ClusterIP Services.
Traffic between Traefik and the server stays inside the remote cluster.
The server runs directly without certificate files or a reload wrapper.

Terraform changes a pod annotation when the token Secret's resource version changes.
This triggers a server rollout after token rotation.
Active connections disconnect during a rollout.
The home client reconnects automatically after a restart.

## Local validation

Run from the `iac` repository root:

```sh
devenv shell -- terraform -chdir=envs/mhemeryck/frp init -backend=false
devenv shell -- terraform -chdir=envs/mhemeryck/frp validate
```

These commands do not contact the state backend or change cluster resources.

## Deployment

Run these steps only when ready to deploy.
Run commands from the `iac` repository root.

- [ ] Review and apply the node root for the DNS record
- [ ] Initialize the frp state backend

```sh
devenv shell -- terraform -chdir=envs/mhemeryck/frp init -reconfigure
```

- [ ] Plan the frp resources with a fresh SecretSpec kubeconfig

```sh
devenv shell -- secretspec run --provider pass \
  --reason "Plan the Home Assistant remote tunnel" -- \
  nu -c 'with-env {TF_VAR_kubeconfig_path: $env.KUBECONFIG} { terraform -chdir=envs/mhemeryck/frp plan }'
```

- [ ] Review the plan and apply the frp root

```sh
devenv shell -- secretspec run --provider pass \
  --reason "Deploy the Home Assistant remote tunnel" -- \
  nu -c 'with-env {TF_VAR_kubeconfig_path: $env.KUBECONFIG} { terraform -chdir=envs/mhemeryck/frp apply }'
```

Terraform waits for the server rollout.
Certificate issuance happens independently through cert-manager.

- [ ] Wait for certificate issuance and server rollout

```sh
secretspec run --provider pass --reason "Check tunnel certificate issuance" -- \
  kubectl wait -n frp --for=condition=Ready certificate/homeassistant-remote-tls --timeout=180s
secretspec run --provider pass --reason "Check tunnel server rollout" -- \
  kubectl rollout status -n frp deployment/frps --timeout=180s
```

- [ ] Copy the generated token directly into the home client's pass entry

```sh
devenv shell -- terraform -chdir=envs/mhemeryck/frp output -raw frp_token \
  | pass insert --multiline secretspec/homeassistant-tunnel/default/FRP_TOKEN
```

- [ ] Deploy the home client using `homelab/picl/frp/README.md`
- [ ] Test login, live updates, and the Companion app over mobile data
- [ ] Test client reconnection after a server restart

## Token rotation

Replace `module.frp.random_password.token` through a reviewed Terraform plan when rotation is required.
Copy the new sensitive output into the same pass entry.
Refresh the home Secret and restart the home client using its README.
Terraform rolls out the server with the new token.
Access resumes when both sides use the same token.
